# 论文研究技能可视化工作流

本文档描述 `paper-research-workflow` 从“输入论文”到“知识库与创新挖掘”的完整工作流。

## 总流程

```mermaid
flowchart TD
    A[用户调用 paper-research-workflow] --> B{是否已配置默认工作区?}
    B -->|否| C[询问用户选择长期论文库目录]
    C --> D[setup 保存 .paper-workspace.json]
    B -->|是| E[接收本地 PDF 路径]
    D --> E

    E --> F{是否优先使用 MinerU?}
    F -->|否| G[轻量提取 pdftotext 或 pypdf]
    F -->|是| H{MinerU 后端选择}

    H -->|standard-cloud| J[高质量云 MinerU]
    H -->|local| K{本地 Docker MinerU 已启用?}
    H -->|agent-cloud| L[轻量云 MinerU]
    H -->|auto| M[按 token -> local Docker or mineru -> agent-cloud 顺序自动选择]

    M --> J
    M --> K
    M --> L
    K -->|是| K1[内置 Docker MinerU]
    K -->|否| K2[先询问用户是否要启用]
    K2 -->|确认| K3[执行 local-mineru --enable]
    K2 -->|未确认| K4[回退其它后端或停止]

    G --> N[生成 extracted/_incoming]
    J --> N
    K1 --> N
    K3 --> K1
    L --> N

    N --> O[text.md tables.md equations.md figures.md manifest.json]
    O --> P[生成 paper_id]
    P --> Q[自动分类 classify_text]
    Q --> R[归档 PDF 到 papers/by-domain 和 papers/by-year]
    R --> S[写入 knowledge/papers orlt paper-id.json]
    S --> T[更新 state/papers.json]

    T --> U{用户要哪种阅读输出?}
    U -->|通俗解释| V[生成通俗解释]
    U -->|专家阅读| W[生成专家阅读]
    U -->|复现计划| X[生成复现计划]
    U -->|创新挖掘| Y[生成创新候选]

    V --> V1{用户满意吗?}
    W --> W1{用户满意吗?}
    X --> X1{用户满意吗?}

    V1 -->|否| V2[再次 refine 讲解]
    W1 -->|否| W2[再次 refine 分析]
    X1 -->|否| X2[再次 refine 复现路径]

    V2 --> V3{覆盖还是新版本?}
    W2 --> W3{覆盖还是新版本?}
    X2 --> X3{覆盖还是新版本?}

    V3 -->|覆盖| V4[更新当前 card]
    V3 -->|新版本 推荐| V5[保存新版本 card]
    W3 -->|覆盖| W4[更新当前 expert reading]
    W3 -->|新版本 推荐| W5[保存新版本 expert reading]
    X3 -->|覆盖| X4[更新当前 reproduction]
    X3 -->|新版本 推荐| X5[保存新版本 reproduction]

    V1 -->|是| Z[同步更新 knowledge/papers orlt paper-id.json]
    W1 -->|是| Z
    X1 -->|是| Z
    V4 --> Z
    V5 --> Z
    W4 --> Z
    W5 --> Z
    X4 --> Z
    X5 --> Z

    Y --> Y1[按合理性 score 评分]
    Y1 --> Y2[按 rank 从高到低排序]
    Y2 --> Y3[写入 innovation brief]
    Y3 --> Y4[append-only 追加到知识库]
    Y4 --> Z
```

    D4 --> E

## MinerU 云端细化流程

```mermaid
flowchart TD
    A[standard-cloud] --> B{是否已有 MINERU_TOKEN 或已保存 token?}
    B -->|否| C[提示先运行 configure-mineru]
    B -->|是| D[POST file-urls/batch]
    D --> E[获取 batch_id 和 upload_url]
    E --> F[低层 HTTPS PUT 上传 PDF 到 OSS 预签名地址]
    F --> G[GET extract-results/batch orlt batch_id]
    G --> H{是否完成?}
    H -->|否| G
    H -->|是| I[下载 full_zip_url 或 markdown_url]
    I --> J[解压并归一化为 text.md 等文件]
```

## 创新排序与入库

```mermaid
flowchart TD
    A[用户基于多篇论文提问创新方向] --> B[读取 knowledge/papers 下相关论文]
    B --> C[生成多个创新候选]
    C --> D[为每个候选计算 score]
    D --> E[按 rank 从高到低排序]
    E --> F[生成 innovation brief]
    F --> G[追加写入 knowledge/innovations]
    G --> H[同步更新 knowledge/papers 中 innovation 相关字段]
    H --> I[保留旧创新历史 不覆盖]
```

## 说明

- `knowledge/papers/<paper-id>.json` 是核心机器可读主记录。
- `cards`、`expert-readings`、`reproductions`、`innovations` 是面向人阅读的 Markdown 产物。
- `state/papers.json` 记录每篇论文已经完成到哪个阶段。
- 多篇论文共享同一个长期工作区，后续新论文进入时会在各自目录下新增同级文件。
- 本地 `local` 后端优先走技能包内置的 Docker MinerU；如果尚未启用，先询问用户是否要启用，确认后再执行 `python scripts/paper_workflow.py local-mineru --enable`。
- `local-mineru --status` 会区分 Docker 未安装、Docker daemon 未启动、镜像未构建三种状态；`local-mineru --enable` 可直接指定 `--docker-dir`，优先通过官方源码归档和 `--source-subdir` 准备完整构建上下文，只有必要时才回退到 `--dockerfile-url`。
- 阅读类输出现在支持“用户不满意就继续优化”，并在覆盖或另存新版本之间做选择，推荐默认保留旧版并另存新版本。
- 创新挖掘现在支持基于多篇论文生成排序结果，并以 append-only 方式追加到知识库，不覆盖旧创新历史。
